# 工单 · 跨机器与多 harness 运维

依据：[跨机器运维专题](../docs/multi-machine-operations.md)、[时间约定](../docs/time-synchronization.md)与[共用执行规则](README.md#所有工单共用的执行规则)。

```text
目标：<本次要完成的实际任务>
现有授权：<准确目标、可读写范围、允许的运行动作>
发起端：<机器、harness/版本、启动方式>
执行端：<实际机器、系统用户、工具路由、cwd>
副本与运行资源：<仓库版本/未提交改动、服务、数据或产物>
正在进行的原任务：<目标 + 管理器 + job/unit 标识；未知就写未知>

先核实真实执行位置、身份、工具版本、配置来源和任务需要的非交互环境。
工具经 SSH、MCP、容器或远程 daemon 执行时，继续定位最终资源所在位置。
只记录必要信息和凭据加载位置，不复制凭据值或完整环境。

指出哪些资源由多个任务共享；按准确对象安排本次写入责任。
独立 worktree/会话不自动隔离服务、全局配置、账号、数据库和挂载数据。
在已有授权内选用可用的运行方式，确认断线、退出、重启与结果保留语义。

有副作用的任务提交前保留原任务定位信息；若接口支持幂等键，保留原值。
超时、丢确认或更换 harness 后，先查原任务；仍在运行就接着观察。
结果未知时先定位，确认完成则验收产物，确认失败后按支持的恢复方式继续。
具体取消或停止要查询最终状态，不能把 UI Stop 等同于远端已取消。

时间记录区分事件发生、观察与 hook 生成；带偏移，明确用户时区和快照新鲜度。
交接只携带目标、范围、版本、原任务、准确结果位置、未决项及必要恢复方式。
接手者用自己的真实路径复核已有权限；已授权工作继续，不重复提交同一写任务。

回报：实际在哪执行；变更和运行版本；原任务最终状态；产物在哪里；
哪条真实用户路径已通过；还未验证什么；后续怎样查询或接手。
真实机器、账号、路径和运行记录留在 owner 私有位置，不提交公开仓库。
```
