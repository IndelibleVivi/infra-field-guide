# 工单 · CC 环境盘点、清理与恢复

依据：[CC 转生资料与路径清单](../docs/06-account-recovery.md)。

执行顺序与第 06 章一致：先退出写入者，完成并抽查 logout 前的原始私有备份；只有所选范围包含已保存登录时，才在原配置仍在原位时 logout。logout 会启动程序，完成后再次确认 CLI、Desktop、IDE 扩展和后台任务不再写入，然后按 A/B 二选一隔离并逐项读回。只清缓存时不强制 logout；可选卸载／重装另列分支，不替代备份与隔离。

```text
读本仓库 AGENTS.md、agents/README.md 与第06章。
目标：<OS、Claude产品与版本、安装方式、真实配置目录>
诉求：<定位旧登录 / A选定状态清理 / B完整重建 / 恢复已有备份>
已见错误：<脱敏提示>
当前授权：<只读盘点 / 精确列出的备份、logout、隔离、站点数据操作>
备份位置：<owner控制的本地路径；不在工单里放凭据>

完成所有已授权的步骤；范围明确后不重复请求同一授权。
诊断平台状态、认证来源、网络与本地文件，不能仅凭401/403推断封禁原因。
保留第06章两套材料的实际差异，不擅自把完整重建缩成申诉建议。
逐项盘点CLI配置/旁边状态文件、项目资产、Desktop、浏览器profiles、IDE、Keychain。
文件不存在标记absent，不能补造；缓存名称不能证明它是认证凭据或封禁指纹。
不输出token、Cookie、Keychain secret、环境变量值或完整私有历史。

任何清理前核对精确目标、writer、symlink、空间、备份与恢复路径。
用原始私有备份保存证据；另建恢复包，复制一份不等于已清理。
A保留目录大部，B重建完整用户配置；按owner选定范围执行。
不把通配删除、全浏览器清空、全Keychain批删当成默认步骤。
每层修改后验证；错误、碰撞、重建中的writer必须先定位，不继续覆盖。
重建后逐项恢复Skills、说明、settings/hooks/MCP和所需历史，保留新旧数据。

收尾给出：路径级操作及恢复位置、资产抽查、当前认证来源、平台账号状态、未验证项。
社区“零痕迹”或“不会再封”只可作为有归属的说法，不能写成你的验收结论。
备份销毁、账号提交与外部上传只在本次明确授权内执行。
```
